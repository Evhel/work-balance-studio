# Перенос сайта «ARV. Трудозатраты» на офисный сервер

Инструкция для системного администратора. Итог: сайт и база данных работают
внутри офисной сети, снаружи доступа нет (только через VPN), код лежит на GitHub.

## 1. Код на GitHub

В редакторе Lovable нажмите кнопку GitHub в правом верхнем углу и подключите
репозиторий. Дальше код синхронизируется в обе стороны: правки в Lovable
попадают в GitHub, правки в GitHub — обратно в Lovable.

Клонирование на сервере:

```sh
git clone <адрес-репозитория> arv
cd arv
```

## 2. База данных внутри сети

Сайту нужна база Supabase, развёрнутая на вашем сервере (self-hosted):

```sh
git clone --depth 1 https://github.com/supabase/supabase
cd supabase/docker
cp .env.example .env      # задайте пароли, JWT_SECRET, ANON_KEY, SERVICE_ROLE_KEY
docker compose up -d
```

После запуска проверьте и примените миграции из этого репозитория. Команда не
содержит паролей: SQL выполняется внутри локального контейнера PostgreSQL.

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\apply-migrations.ps1 -ValidateOnly
powershell -ExecutionPolicy Bypass -File .\deploy\apply-migrations.ps1
```

Повторный запуск безопасен: применённые файлы пропускаются, а изменение уже
применённой миграции обнаруживается по SHA-256 независимо от переводов строк
Windows/Linux. `deploy/schema.sql` остаётся
снимком конечной структуры только для аварийного развёртывания чистой базы.

В настройках Supabase включите вход по email/паролю, автоподтверждение адресов
и отключите самостоятельную регистрацию — сотрудников заводит модератор или
офис-менеджер прямо на сайте.

## 3. Настройки сайта

```sh
cp .env.example .env
```

и подставьте адрес вашей базы и три ключа (anon, service role). Файл `.env`
в репозиторий не попадает.

## 4. Запуск сайта

Через Docker:

```sh
docker compose up -d --build
```

Или без Docker (нужен Node 22+ и bun):

```sh
bun install
NITRO_PRESET=node_server bun run build
PORT=3000 node .output/server/index.mjs
```

Сайт будет доступен по адресу `http://<ip-сервера>:3000`. Обычно перед ним
ставят nginx с доменным именем вида `arv.office.local` и сертификатом.

## 5. Доступ только из офиса и по VPN

- В `docker-compose.yml` порт привязан к внутреннему IP сервера — замените
  `192.168.0.10` на реальный адрес.
- На фаерволе разрешите входящие подключения к портам сайта и базы только с
  подсетей офиса и VPN, всё остальное — запретить.
- Никаких проброшенных портов на внешний роутер: удалённые сотрудники
  подключаются к офисному VPN и попадают на сайт как из офиса.

## 6. Первый вход

Откройте сайт, страница `/auth` предложит создать первую учётную запись
модератора. Дальше модератор и офис-менеджер заводят сотрудников на странице
«Новый сотрудник».

## 7. Резервные копии

```sh
pg_dump "postgresql://postgres:ПАРОЛЬ@localhost:5432/postgres" > arv-$(date +%F).sql
```

Поставьте эту команду в ежедневное расписание (cron) и храните копии на
отдельном диске.
